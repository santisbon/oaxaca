# oaxaca-session

The graphics and session metapackage: roadmap step 4. Installing `oaxaca-session` on top of `oaxaca-base` pulls in Mesa, Hyprland with Xwayland, uwsm, SDDM with Qt's Wayland plugin, the desktop portals, GNOME Keyring (the secret store desktop applications keep credentials in, with the PAM module that unlocks it with the login password), Quickshell 0.3.2 or newer (from our repository; the Qt/QML toolkit the desktop shell runs on), and `oaxaca-nvidia` for the NVIDIA install path. `scripts/rootfs-create.sh` installs this package when building the `session` profile of the root filesystem. See `docs/4 - session.md`.

Files this package installs besides its dependency list:

| Installed path | Purpose |
|---|---|
| `/etc/sddm.conf.d/10-oaxaca-wayland.conf` | SDDM's greeter runs on Wayland, under a Hyprland instance started with the file below |
| `/usr/share/oaxaca/sddm/hyprland.lua` | the Hyprland configuration for that greeter instance: no logo, no splash, no wallpaper, no animations |
| `/usr/lib/systemd/user/oaxaca-volume-monitors.service` | a user unit, enabled for every user and wanted by `graphical-session.target`, that runs `gio mount -l` once right after login, so gvfs's volume monitors start in the background instead of when Files first opens; the camera monitor spends 2 to 4 s probing a connected iPad, and Files' first launch of a session waited for it (`docs/7 - image-installer.md`, choice 46) |
| dependencies on `rtkit`, `steam-devices`, `libmtp-runtime`, `libimobiledevice-utils`, `ipp-usb`, `cups-browsed`, `system-config-printer-udev` | what a stock Ubuntu installs through Recommends, which are off here (choice 47): PipeWire's realtime priority; udev rules giving the user access to game controllers' raw devices for Steam Input (`steam-installer` does not pull them in at all); udev rules for MTP phones and players; `idevicepair` and the other iPhone and iPad tools; driverless USB printers, network printer discovery and set-up on plug-in |
| dependency on `usbmuxd` | the service through which Linux talks to iPhones and iPads, which gvfs's Apple device monitor (`gvfs-afc-volume-monitor`) needs for Files to browse them; `libimobiledevice` only recommends it, and Recommends are off (choice 46) |
| `/usr/lib/systemd/user-environment-generators/50-oaxaca-gpu` | a systemd user environment generator that exports `AQ_DRM_DEVICES`, the GPU list Hyprland's backend renders on, from `oaxaca.gpu=` on the kernel command line, else `/etc/oaxaca/gpu` (one device per line, installed by a hardware package such as `oaxaca-hw-legion`; used only when a GPU it names drives the display the firmware booted on, so a laptop switched to its discrete GPU in the firmware skips it, choice 45), else, in the live session on a dual-GPU machine, the firmware's boot GPU; on hybrid graphics with an NVIDIA GPU beside an Intel or AMD display GPU it also points applications' EGL and Vulkan at Mesa, so starting one does not wake the NVIDIA GPU, and exports `OAXACA_GPU_OFFLOAD=nvidia` (choice 34); with an AMD GPU beside the display GPU and no NVIDIA one it exports `OAXACA_GPU_OFFLOAD=amd` and the AMD GPU's address in Mesa's `DRI_PRIME` form, `OAXACA_GPU_OFFLOAD_DEVICE` (choice 43); `tests/gpu-env/run.sh` checks both against made-up machines; by-path names are resolved to the card's node at login because aquamarine fails to start on the symlink (`docs/7 - image-installer.md`, choice 17, 2026-10-11) |
| `/usr/lib/udev/rules.d/60-oaxaca-session.rules` | write access to `/sys/class/backlight/*/brightness` and `/sys/class/leds/*/brightness` for the `video` group: the port's brightness commands call brightnessctl, which writes sysfs directly, and Ubuntu's brightnessctl ships no rule and no logind support; the installer's `users.conf` and the live session put the user in `video` (`docs/7 - image-installer.md`, choice 15, 2026-10-11) |

No user, default session or login setting is configured here, and Oaxaca sets no autologin: a user logs in with a password. SDDM finds the session through `hyprland-uwsm.desktop`, which Ubuntu's `hyprland` package ships under `/usr/share/wayland-sessions/`; the installer (roadmap step 7) chooses the default session and the user.
